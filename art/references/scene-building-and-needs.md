# 场景、建造与自主生活

## 核心问题

能否借鉴《模拟人生》的分层场景、房间编辑和需求驱动行为，在当前浏览器原型中形成可建造、可通行、可自主生活的世界，并为指定真实地点的数据映射留出边界？

## 研究范围与来源

不将闭源游戏的内部网格结构、DCC 软件版本、材质算法或行为调度细节写成已知事实。玩家可观察机制与本项目的工程实现是两件事。

五个一手资料入口：

1. [EA 官方 The Sims 4 手册](https://eaassets-a.akamaihd.net/eahelp/manuals/the-sims-4-ps4-pt.pdf)：用于核对生活/建造模式、需求和控制分区，先前已下载并检查。
2. Maxis Terrain Tools 官方直播及 SimGuru 原始说明：地形抬高、降低、平整和坡度可达性；原始链接由 [EA 论坛来源汇编](https://forums.ea.com/discussions/the-sims-4-general-discussion-en/re-terrain-tools-patch-simgurumaxis-sourced-info/1492127) 保留。本轮读取的是汇编，不把社区转述当成引擎源码证据。
3. David “Rez” Graham，[An Introduction to Utility Theory](https://www.gameaipro.com/GameAIPro/GameAIPro_Chapter09_An_Introduction_to_Utility_Theory.pdf)，Game AI Pro 第 9 章：本轮读取，用于动作评分、距离代价和惯性设计，不声称本项目复制了 Sims 4 的精确公式。
4. [OpenStreetMap 数据模型与建筑标签](https://wiki.openstreetmap.org/wiki/Key:building)：真实映射时核对建筑轮廓、层数和高度字段，尚未读取任何指定区域数据。
5. [Copernicus DEM](https://dataspace.copernicus.eu/explore-data/data-collections/copernicus-contributing-missions/collections-description/COP-DEM)：真实映射时核对高程来源、分辨率和许可，当前没有下载高程栅格。

补充机制证据：[SheriGR 墙体与房间教程](https://sherigr.com/sims-4-building-tutorials/wall-and-basement-tools/)，视频 00:22 墙工具、00:57 矩形房间工具、01:28 地板/天花板、03:12 拆墙。教程明确区分单墙与完整房间，房间可自动产生地板，拆墙涉及退款。

关注的五项信号：

- 建造操作是否同时改变网格、可见开口与导航障碍。
- 房间地板与家具/居民高度是否共用基准，而非分别猜测。
- 草地是否由远景地表和近景植被共同构成，建筑/道路能否排除草叶。
- 家具是否提供接近点、姿态点、进入/退出流程，而非仅附带按钮。
- 自主行为是否先验证设施可达性，并在手动指令、暂停和编辑期间让出控制。

待检验假设：采用相似的场景组织方式，就足以把真实世界直接变成可生活的游戏。

会改变方案的发现：目标区域若存在带门窗、楼层和室内布局的授权 BIM/CityGML/扫描数据，能从“外观近似”推进到可进入建筑；只有航拍、轮廓和高程时，室内布局及活动点仍需人工制作或明确标为生成内容。

## 场景如何拆解

《模拟人生》是游戏引擎、场景工具和行为系统共同工作的结果，不能等同于一份 Blender 场景。可借鉴的工程分层如下；这是适用于本项目的实现方案，不是对闭源引擎内部的逆向结论。

| 层次 | 负责什么 | 当前 Sunny Life 实现 |
| --- | --- | --- |
| 世界布局 | 河岸、高台、道路、建筑与目的地位置 | `world-layout.json`、`terrain.js` |
| 地表 | 高度、坡度、可行走区、材质差异 | 多边形地块、地表噪声、共享高度查询 |
| 植被 | 树木、近景草叶、路面/建筑排除 | Blender 树木，实例化弯曲草叶和风 |
| 建筑 | 地板、墙段、门窗开口、剖面与屋顶 | `architecture.js` 统一几何记录 |
| 可交互物件 | 占地、接近点、坐点/站点、恢复效果 | `game.js`、`interactions.js` |
| 人物 | 蒙皮、动作、身体比例、接触校正 | Blender + GLB + AnimationMixer |
| 自主生活 | 需求衰减、候选评分、执行、取消 | `autonomy.js` + `ActivityRunner` |

视觉素材是可复用部件。门洞改变碰撞，草叶避开房间，沙发坐点关联模型尺寸，动画必须在真实目的地执行，这些约束比单纯增加模型精度更重要。

## 本轮实现

- 地块内按住拖动绘制正交墙段；也保留起点/终点两点击操作。
- 拖矩形房间，同时产生地板、四面墙和一个门洞；相邻完整共用边不重复建墙。
- 原始外墙、自定义墙都可拆，渲染和导航同步；房间地板可拆。
- 门窗工具在墙上设置一个开口；门可通行、窗不可通行。再次设置会替换该墙段的原开口，不是无限叠加。
- 清空建筑与家具需要确认，可撤销，居民、时间和需求不重置。
- 两方向旋转、俯仰、缩放、正交/透视、自动剖墙和回家取景。画墙/房间期间相机不会抢走单指/左键拖动。
- 新世界默认有卫浴；旧存档不自动添加建筑，可在房屋属性中“添加卫浴间”，或者自行从目录放置马桶和淋浴。
- 马桶：前往、坐下、隐私屏风、如厕、冲水、起身退出。
- 淋浴：前往、进入、隐私围挡、水流和洗浴手势、退出。采用非裸露表现，不模拟脱衣。
- 六项需求按不同速率衰减；自主照料筛选真实可达设施，以紧急程度、恢复量和距离评分；完成真实行为后才恢复需求。
- 自动动作不改变镜头，手动指令优先；无设施或堵路时等待重试，不凭空恢复需求，不反复通知。
- 旧 v1 存档及导入均补齐缺失字段，保留房屋、家具、角色与预算。
- 导入头部采用共享截口顶点延伸颈部连接环，向 Chest 权重过渡；补肩片和袖顶权重，不再夹窄脖子假装连接。

## 真实世界映射

可以沿用分层方式，但需先指定城市/街区和范围。建议先做几百米见方的区域，按米制局部坐标建立原点。

1. 获取授权建筑轮廓、道路/水域、土地覆盖和高程；记录来源、坐标系、分辨率及许可。
2. 坐标投影到局部米制坐标，按采样分辨率生成地表；道路、坡度、水域共同约束导航。
3. 建筑轮廓与有来源的高度生成外壳，缺失高度明确使用估计，不把它标为实测。
4. 选择重点建筑补门窗、室内平面和可交互家具。照片或 3D Tiles 的视觉外壳本身不提供可生活语义。
5. 把室内房间、室外路径和跨层连接统一到导航系统，并验证人物碰撞与活动可达性。
6. 大范围世界再考虑分块、LOD、导航网格分区及资源流式加载。

当前没有 GIS 导入器，也没有将青禾镇映射到任何真实地点。不能将虚构小镇描述为真实世界还原。

## 边界

当前为单层矩形房间编辑，不支持任意闭环墙自动识别地板、斜墙、多层楼梯、完整门扇动画或建筑室内生成。邻居仍是简化的散步/聊天角色，自主需求仅管理玩家居民。阅读与园艺仍是可达位置加简化活动，未增加复杂手部工作。没有疾病、死亡、职业或家庭系统。

颈部拓扑已检查男女两种模型：1.75 米以下连接区开放边缘均为 0，最低点在 1.61 米衣领内。该检查不意味着任意动作、任意服装组合绝对不会穿模；仍以实际姿态截图和有范围的碰撞测试为准。
